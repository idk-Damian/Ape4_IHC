## Caso desarrollado

CaféU es una cafetería universitaria ficticia. El estudiante necesita consultar productos y preparar un pedido durante su descanso. El escenario contiene un café americano de $1,50 y un sanduche de $2,75, con una unidad de cada producto y un total de $4,25. La persona puede confirmar el pedido o editarlo antes del envío.

## Objetivo

Diseñar un prototipo de baja fidelidad que permita consultar productos y gestionar un pedido mediante una estructura de información, navegación y controles coherentes con las necesidades del estudiante.

## Explicación didáctica

La documentación desarrolla la secuencia **Requisito → Pantalla → Sitemap → User flow → Componentes → Wireframe** utilizando RF05, que permite modificar cantidades o quitar productos antes de confirmar. Incluye la justificación de las decisiones, las respuestas para la defensa, la trazabilidad, conclusiones y recomendaciones.

## Alcance de la revisión

Se documentan cuatro pantallas principales y dos secundarias. Las capturas muestran el recorrido normal y el pedido de $4,25. La eliminación del sanduche produce un total esperado de $1,50; dos cafés y un sanduche producen $5,75. Los cambios y mensajes de error se describen como comportamientos previstos, no como pruebas de ejecución ni mediciones con usuarios.

## Trabajo colaborativo

Las contribuciones deben registrarse con commits que identifiquen su autor y el producto modificado. Cada integrante debe aportar cambios o revisiones reales y poder explicar su participación. El historial del repositorio sirve como evidencia de la evolución del trabajo.
